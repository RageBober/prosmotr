# prosmotr

Лёгкий просмотрщик документов и данных под Linux. Только чтение — ничего не редактирует, ничего не портит.

Умеет: **markdown**, **pdf**, **xlsx / xls / ods**, **docx / odt**, **csv / tsv**,
**json / yaml / toml / xml**, картинки, текст, логи и код с подсветкой.

Открытые файлы живут во вкладках, папки слева сворачиваются, вкладки — тоже.

Собранный бинарник — **5,4 МБ**, из них полтора занимает pdf.js.
Электрон на этой же задаче весит около 150 МБ.

## Установка и обновление одной командой

```bash
curl -fsSLO https://raw.githubusercontent.com/RageBober/prosmotr-/main/install.sh
bash install.sh
```

Скрипт смотрит последний релиз, скачивает `.deb` и ставит его. Той же командой
делается обновление: если установленная версия не старее — он молча выйдет,
ничего не трогая.

```bash
bash install.sh --check    # что стоит и что доступно, без установки
bash install.sh --binary   # без пакета: бинарник в ~/.local/bin
```

Скачивайте и запускайте двумя шагами, а не `curl … | bash`: так вы можете
прочитать скрипт перед тем, как дать ему sudo. Он короткий.

### Вручную

Готовый бинарник и `.deb` лежат в разделе Releases (в репозитории их нет:
собранным файлам не место в истории).

```bash
sudo apt install ./prosmotr_0.1.0_amd64.deb   # пакет: иконка в меню и «Открыть с помощью»

# или без пакета
sudo apt install libwebkit2gtk-4.1-0
chmod +x prosmotr-x86_64
./prosmotr-x86_64 ~/Документы
```

Собран против glibc 2.39 и WebKitGTK 2.52 — то же, что стоит в Ubuntu 26.04,
так что версии совпадают. Остальные библиотеки (`libsoup-3.0`,
`libjavascriptcoregtk-4.1`, `libgtk-3`) подтянутся как зависимости.

## Собрать самому

Системные зависимости (один раз):

```bash
# Ubuntu 24.04 / 26.04, Debian, Mint
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev patchelf build-essential curl

# Fedora
sudo dnf install webkit2gtk4.1-devel gtk3-devel librsvg2-devel patchelf

# Arch
sudo pacman -S webkit2gtk-4.1 gtk3 librsvg patchelf
```

Rust, если ещё нет: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`

Запуск и сборка:

```bash
cargo run --release              # запустить
cargo test -p prosmotr-core      # тесты ядра, без GUI, ~1 секунда
cargo build --release            # бинарник в target/release/prosmotr
```

Пакеты `.deb` и `.AppImage`:

```bash
cargo install tauri-cli --version "^2"
cargo tauri build
# готовое лежит в target/release/bundle/
```

Выпуск новой версии: поднять `version` в `Cargo.toml` и `tauri.conf.json`,
затем поставить тег — дальше CI соберёт пакет и приложит его к релизу сам.

```bash
git tag v0.2.0 && git push origin v0.2.0
```

## Как устроено

```
prosmotr/
├── core/            крейт prosmotr-core — вся работа с файлами, без GUI
│   └── src/
│       ├── doc.rs       ← шесть форм документа и диспетчер по расширению
│       ├── text.rs      ← чтение с диска, UTF-8 и windows-1251
│       ├── scan.rs      ← обход папки, естественная сортировка имён
│       └── formats/     ← по файлу на формат
├── src-tauri/       окно и шесть команд — тонкая прослойка
│                    (выбор папки, список файлов, чтение документа и байтов)
└── dist/            интерфейс: index.html + app.css + app.js
    └── vendor/      pdf.js и подсветка синтаксиса, лежат внутри — интернет не нужен
```

**Главное решение.** Форматов может быть сколько угодно, но наружу они выходят
всего в шести формах:

| Форма | Что показывает | Кто отдаёт сейчас |
| --- | --- | --- |
| `Text` | текст с номерами строк и подсветкой | txt, log, код, конфиги |
| `Html` | готовую разметку | markdown, docx, odt |
| `Table` | таблицу с сортировкой и фильтром | csv, tsv, xlsx, xls, xlsb, ods |
| `Tree` | сворачиваемое дерево | json, yaml, toml, xml |
| `Page` | страницы pdf | pdf |
| `Image` | картинку с масштабом | png, jpg, gif, webp, svg, avif |

Интерфейс знает эти шесть форм и **не знает ни одного расширения**. Поэтому
`app.js` почти не растёт, когда в ядро добавляют новый формат.

Второе следствие: ядро ничего не знает про окно, поэтому оно покрыто обычными
юнит-тестами и собирается за секунды, без WebKit.

## Как добавить формат

На примере `.xlsx` — ровно так он и добавлялся.

**1.** Зависимость в `core/Cargo.toml`:

```toml
calamine = "0.36"
```

**2.** Новый файл `core/src/formats/excel.rs`:

```rust
use crate::Doc;
use calamine::{open_workbook_auto, Data, Reader};
use std::path::Path;

pub fn read(path: &Path, max_rows: usize) -> Doc {
    let Ok(mut wb) = open_workbook_auto(path) else {
        return Doc::Unsupported { ext: "xlsx".into(), message: "Не открылось".into() };
    };
    let Some(Ok(range)) = wb.worksheet_range_at(0) else {
        return Doc::Unsupported { ext: "xlsx".into(), message: "Нет листов".into() };
    };

    let mut it = range.rows();
    let columns = it.next()
        .map(|r| r.iter().map(cell).collect::<Vec<_>>())
        .unwrap_or_default();
    let rows: Vec<Vec<String>> = it.take(max_rows)
        .map(|r| r.iter().map(cell).collect())
        .collect();

    Doc::Table {
        total_rows: range.height().saturating_sub(1),
        truncated: rows.len() < range.height().saturating_sub(1),
        columns, rows,
        delimiter: "лист 1".into(),
    }
}

fn cell(d: &Data) -> String { d.to_string() }
```

**3.** Одна строка в `core/src/formats/mod.rs`:

```rust
pub mod excel;
```

**4.** Одна строка в диспетчере `core/src/doc.rs`:

```rust
"xlsx" | "xls" | "ods" => Ok(formats::excel::read(path, limits.max_rows)),
```

Всё. Интерфейс трогать не нужно — форма `Table` у него уже есть, вместе с
сортировкой по столбцам, фильтром и догрузкой строк при прокрутке.

Так же добавились docx, odt, yaml, toml и xml: по файлу в `formats/` и по строке
в диспетчере, ноль правок в `app.js`. Дописывать интерфейс пришлось ровно
дважды — под pdf (страницы рисует pdf.js) и под картинки. Остальное легло
в готовые формы.

## Что уже сделано

**Форматы**

- markdown с таблицами, сносками, списками задач — рендер в Rust (`pulldown-cmark`), без javascript-библиотек
- pdf: страницы рисуются по мере прокрутки, масштаб кнопками; сотня страниц не кладёт окно
- xlsx / xls / xlsb / ods через `calamine`, с именем листа в шапке
- docx / odt: свой разбор zip+xml — заголовки, жирный, курсив, списки, таблицы
- csv/tsv: угадывание разделителя (`,` `;` таб `|`) с учётом кавычек — русский Excel сохраняет с точкой с запятой
- json / yaml / toml / xml деревом; у xml атрибуты идут как `@имя`, одноимённые теги — списком
- картинки: масштаб «вписать / 100%», размер в пикселях
- код с подсветкой синтаксиса, номера строк, языки определяет ядро

**Работа с файлами**

- вкладки: `Ctrl+Tab` между ними, `Ctrl+W` закрыть, `Ctrl+1…9` по номеру, средняя кнопка мыши тоже закрывает
- разобранный документ кешируется во вкладке — переключение мгновенное
- дерево папок сворачивается по одной или все разом
- полоса вкладок сворачивается целиком, если мешает
- запуск с путём: `prosmotr ~/Документы` или `prosmotr план.md` — во втором случае откроется папка файла, а сам файл встанет вкладкой
- «Открыть с помощью» из файлового менеджера работает через тот же путь: пакет ставит `.desktop` с нужными типами файлов
- windows-1251 как запасная кодировка: выгрузки из 1С читаются без кракозябр
- обрезка гигантских файлов по границе символа UTF-8
- ссылки между файлами внутри папки открываются в самом просмотрщике
- оглавление по заголовкам, фильтр по именам, тёмная и светлая темы
- 50 тестов на ядре, включая настоящие xlsx и docx

## Ограничения, о которых стоит знать

- csv и xlsx читаются в память целиком; для файлов больше ~200 МБ нужен потоковый режим (следующий шаг — отдавать строки страницами через ту же форму `Table`)
- в таблицу попадает только первый лист книги; переключателя листов пока нет
- docx разбирается по существу: колонтитулы, сноски, картинки внутри документа и точные стили опускаются
- слежения за изменениями файла нет, обновление по кнопке (крейт `notify` — вечер работы)
- окно рисует системный WebKitGTK, поэтому на разных дистрибутивах возможны мелкие различия
